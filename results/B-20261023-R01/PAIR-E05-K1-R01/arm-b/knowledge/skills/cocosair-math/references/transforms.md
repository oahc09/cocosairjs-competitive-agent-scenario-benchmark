## Element layout and storage

|m00  m04  m08 m12|
|m01  m05  m09 m13|
|m02  m06  m10 m14|
|m03  m07  m11 m15|

### Unit mistake: degrees fed to radians APIs

Wrong:

```js
Quat.fromAxisAngle(rot, Vec3.UP, 45);           // 45 RADIANS, not 45 degrees
node.setRotationFromEuler(0, Math.PI / 2, 0);   // 1.57 DEGREES - nearly no rotation
```

Correct:

```js
const rot = new Quat();
const axis = new Vec3();
Quat.fromAxisAngle(rot, Vec3.UP, 45 * Math.PI / 180); // radians in (src/cocos/core/math/quat.ts:475)
node.setRotationFromEuler(0, 90, 0);                  // degrees in (src/cocos/scene-graph/node.ts:2506)
const rad = Quat.getAxisAngle(axis, rot);             // returns radians (src/cocos/core/math/quat.ts:137)
```

The split is by entry point, not by type: the euler family multiplies degrees by `halfToRad` (`quat.ts:558-560`, `:934`) and `Node.setRotationFromEuler` forwards degrees into it (`src/cocos/scene-graph/node.ts:2506-2514`), while the axis-angle family (`quat.ts:475`, `:137`), `Mat4.rotate*` (`mat4.ts:441`) and `Mat3.toEuler` (`mat3.ts:649`) take radians. Mixing them does not throw - it rotates by a factor of about 57, so a 45-degree turn becomes roughly 2578 degrees and a `PI / 2` radian turn is 1.57 degrees.

Consequences that follow from the tables above:

- Handedness: `Vec3.FORWARD` is `(0,0,-1)` (`vec3.ts:62`, comment "we use -z for view-dir"), so a node's local +Z faces away from where it looks; projection builders (`Mat4.perspective` `mat4.ts:1173`, `Mat4.ortho` `:1219`, `Mat4.lookAt` `:1264`, `Mat4.frustum` `:1126`) are consumed by the camera layer, not by nodes.
- Round trip: `Mat4.toSRT(Mat4.fromSRT(m, q, v, s), q2, v2, s2)` reproduces `q`, `v`, `s` only when the scale is non-negative. A mirror is always relocated onto `x`: `toSRT` folds the sign of `Mat3.determinant` into `s.x *= -1` (`mat4.ts:914-917`) and negates the first normalized column before `Quat.fromMat3` (`:920-927`), so the same MATRIX is reproduced while `q2`/`s2` differ from the inputs - measured on `s = (1, -1, 1)` with `q` identity, the read-back is `s = (-1, 1, 1)` and `q` a 180-degree turn about Z; `s = (1, 1, -1)` also reads back `s.x = -1`. Do not treat the triple as the original authoring values; keep the authored `Vec3` scale yourself if a mirror must survive.
- `Mat4.IDENTITY` is frozen (`mat4.ts:63`), so `Mat4.identity(Mat4.IDENTITY)` throws in strict mode while `Mat4.identity(new Mat4())` is the intended reset path.
