# Contracts

- Canvas admission: the browser main entry may be imported before canvas creation. Pass a selected attached canvas to createAirApp; parameter admission precedes PAL screen/input binding. Custom IDs are retained; do not assign pre-import globals or use removed light package entries.
- One runtime per document: admission state lives in `globalThis[Symbol.for('cocosair.bootstrap.v1')]` with status `idle | initializing | ready | failed | closed` (`src/air/app-config.ts:16-30`). Identical normalized options share the init Promise and the app; any difference in the compared fields rejects `AIR_E_APP_CONFLICT`; `closed` rejects `AIR_E_APP_CLOSED`; `failed` rejects `AIR_E_APP_RELOAD_REQUIRED` (`:149-157`). `equalAirOptions` (`:114-121`) compares the `canvas`/`container` elements and the `contextLoss.reload`/`contextLoss.onEvent` callbacks by identity, the remaining scalars and the three `designResolution` numbers by value, so a fresh inline arrow in a second `createAirApp` call rejects `AIR_E_APP_CONFLICT` - pass a stable options object. Rebuilding the low-level runtime requires a whole-page reload.
- Option ranges are hard, not advisory: `renderMode` must be an integer 0..3 (engine `WEBGPU = 4` is rejected at the AIR surface, and `1`/`CANVAS` passes validation but starts no device - see the renderMode rows in [app-options.md](app-options.md) and [startup-errors.md](startup-errors.md)), `pixelRatioCap` a finite positive number (default 2, or a usable `__CCDPR_CAP__`), `designResolution.policy` one of 0..4 with finite positive width/height (`src/air/app-config.ts:63-75`). Out of range throws; nothing is clamped or ignored.
- Startup is a fixed pipeline, and the DPR cap only counts when it lands before the PAL evaluates: context-health attach -> diagnostics channel -> physics selector -> `game.init` -> `view.setDesignResolutionSize` -> the caller's first `run()`, with teardown before rethrow on init failure, the `AIR_E_PIXEL_RATIO_IMPORT_ORDER` / `AIR_E_CANVAS_IMPORT_ORDER` checks and the `round(CSS size * min(devicePixelRatio, cap))` buffer formula all line-cited in [app-options.md](app-options.md) (Startup order).
- Lifecycle gates in `run()` fire in this code order (`src/air/app.ts:135-159`): closed -> `AIR_E_APP_CLOSED`; release in flight -> `AIR_E_SCENE_RELEASING`; previous release failed -> `AIR_E_SCENE_RELEASE_FAILED`; not a valid native `Scene` -> `AIR_E_SCENE`; re-running the current scene -> silent no-op (`:140`), checked before the ownership gate; only a replacement scene then meets `AIR_E_SCENE_RELEASE_REQUIRED` while the current scope owns cleanup callbacks (`:141-143`). `close()` pauses the loop, releases the scene, destroys context-health and diagnostics listeners and marks the registry closed only when this app is the registry's app (`src/air/app.ts:202-203`); it does not restore a lost GL context and does not make the document reusable. Tables: [app-options.md](app-options.md) and [startup-errors.md](startup-errors.md).
- Cleanup is cooperative with a hard deadline and context health never self-heals: `session.dispose()` defaults to 5000 ms and accepts only `(0, 5000]`, and `own()` returns a function that unregisters the callback and never runs it (`src/air/session-scope.ts:50-55`, `:66-71`; [session-scope.md](session-scope.md)); `webglcontextrestored` transitions `restoring` then immediately `failed`, because no GPU resource is rebuilt (`src/air/context-health.ts:171-177`; [context-health.md](context-health.md)).
- Capability layers stay separate: consult build/cocosair.module.d.ts and the installed main exports for API shape; source/bundle presence does not establish current browser verification. There are no separate startup declarations.
