# E01 — 深空星系巡航(Deep Space Galaxy Cruise)

> 冻结规格(Frozen Brief)。本文件为人读版,与同目录 spec.json 机读版必须一致;两者冲突时以 spec.json 为准并触发 SPEC_INVALID 复审。
> 全文使用图形领域语言,不引用任何引擎类名或 API;任何能真实达成下述行为的实现路径均可接受。

## 1. Goal

构建一个完全由程序生成的旋涡星系巡航场景:不少于 50,000 个真实渲染的星点组成带旋臂与核球结构的星系盘,整体持续慢旋;观察者通过鼠标视差与滚轮穿行进行巡航;HUD 实时反馈关键数据;帧率不低于 30fps;提供 Reset 恢复初始观察状态。

## 2. Visual Direction(可判定视觉锚点)

**色彩**
- 背景为接近纯黑的深空色(建议暗于 RGB 16,16,24),无可见梯度断层或压缩色带。
- 星点颜色沿半径呈梯度:核心区偏暖黄白,旋臂中段偏蓝白,外缘偏冷蓝,并散布少量橙红亮星;不得是单一颜色均匀撒点。
- 至少存在 3 档可辨识的星点亮暗层级(核球亮星、盘面普通星、暗弱背景星)。

**构图**
- 初始视角为斜俯视(盘面法线与视线夹角约 30°–60°),星系盘占据画面中央约 60%–75% 宽度。
- 可辨识旋臂 ≥ 2 条(对数螺旋形态),自核球向外延伸;核球呈中央明亮聚集。
- 星系盘具有可感知的厚度与中央隆起(非完全平面纸片)。

**运动**
- 星系绕盘面法线持续慢旋,角速度 0.02–0.1 rad/s(状态以 rotationPhase 暴露);视觉上星点沿切向整体流动,而非画面平移或缩放。
- 鼠标移动产生小幅视差偏移(星系与远景的轻微相对位移);滚轮改变观察距离:近距时星点明显放大变疏,远距时收拢变小。
- HUD 数字实时刷新,帧率数值随负载波动可见变化。

## 3. World Composition

1. **星系盘(主体)**:≥ 50,000 星点;按对数螺旋生成 ≥ 2 条旋臂,叠加随机散布的盘面星;颜色与尺寸按半径及随机分层。
2. **核球**:中心密集亮星群(数千星点,计入星点总数)。
3. **远景背景星(可选)**:静态或极慢的远处星点层,增强纵深。
4. **HUD(2D 覆盖层)**:至少显示星点总数、实时帧率、相机距离;置于画布角落,不遮挡星系主体。
5. **Reset 控件**:HUD 区域内可见的 Reset 按钮(可见文本或 aria-label 为 reset)。

## 4. Interaction & Feedback

| 输入 | 行为 | 状态反馈 |
|---|---|---|
| 指针移动 | 视差偏移(小幅、平滑,基于指针偏离画面中心的有符号偏移) | parallaxOffset 变化 |
| 滚轮向上 | 靠近星系(穿行) | cameraDistance 减小 |
| 滚轮向下 | 远离星系 | cameraDistance 增大 |
| 点击 Reset | 恢复初始观察状态 | epoch +1 |

- 相机距离范围 [40, 400],初始 120(以状态报告单位计);距离变化必须逐帧插值平滑,不得瞬跳。
- 视差偏移幅度不超过画布尺寸的 10%,方向正确、无过冲振荡。
- HUD 数字必须来自真实运行数据(星点数、帧率、距离),与 __bench 状态一致(允许四舍五入显示)。

## 5. Asset Contract

无共享资产。全部星点与结构必须程序化生成(构建期生成数据、运行期渲染均可),不得依赖任何外部图片、模型或预烘焙资源。

## 6. Scale & Performance

- starCount ≥ 50,000;状态报告值必须等于真实提交渲染的星点数量。
- 帧率 ≥ 30fps(以 2 秒滚动平均计;加载完成后的空闲态与交互态均须满足)。
- 星点须以批量方式提交渲染,不得逐星点提交绘制导致明显卡顿。
- __appReady 在页面加载后 10s 内置 true。

## 7. Runtime / Lifecycle

- 页面暴露 `window.__appReady`(场景首帧渲染完成后置 true)。
- 页面暴露 `window.__bench = { getState(): object, reset(): void }`:
  - `getState()` 返回:`starCount`、`rotationPhase`(弧度,初始 0,随时间单调递增)、`cameraDistance`(初始 120)、`parallaxOffset`({x,y},初始 {0,0})、`fps`、`hudVisible`、`epoch`(初始 0)。
  - `reset()`:恢复初始相机距离(120)、视差({0,0})与旋转相位(0);`epoch` +1;恢复过程在 1s 内完成;不得以整页刷新实现。
- 生命周期内不得产生未捕获异常;reset 可连续执行多次且行为一致。

## 8. Technical Constraints

- 场景为浏览器画布上的 3D 实时渲染;禁止以 2D 位图、CSS 动画或 DOM 元素位移冒充。
- 本 Brief 为 API 中立:不预设任何引擎类名或接口;实现方自行选择等价技术手段。
- 星点在视口内须可辨(点尺寸或辉光处理);整体不得暗于像素断言下限(亮像素占比 ≥ 2%)。
- 时间步进基于时钟增量;后台标签页节流不视为失败,恢复前台后须继续正确推进。

## 9. Completion Contract

1. `npm run build` 退出码 0,产物 `dist/` 被 `index.html` 引用。
2. 页面启动后 10s 内 `window.__appReady === true`。
3. `window.__bench = { getState, reset }` 存在且可调用。
4. 全程(加载、交互、reset)无未捕获异常。
5. spec.json 全部探针通过:每个关键 PASS 均有状态证据 + 至少一个独立观测证据(像素/运动/DOM)。

## 10. Forbidden Shortcuts

1. 不得以背景贴图、天空盒图片或预渲染全景图冒充星点渲染("一张图了事")。
2. 不得用 2D 画布位图绘制、CSS 动画或 DOM 元素位移冒充 3D 星系。
3. 不得以 __bench 状态声称代替真实渲染:状态正确但画面为空必须 FAIL(对齐 NC01)。
4. 不得冻结画面而状态仍报告旋转与帧率(对齐 NC02)。
5. 不得将星点数量降至 50,000 以下,或以纹理平铺、重复图元虚报数量。
6. 不得使用预渲染视频、序列帧或 GIF 循环冒充实时渲染。
7. HUD 不得显示与状态/实测不符的硬编码假数据。
8. 不得通过隐藏画布、遮挡视口、把画布缩为 1px 等手段骗过像素断言。
9. reset 不得以 location.reload 或整页刷新实现。
10. 不得探测或篡改 harness/validator(检出即 INVALID_RUN)。
