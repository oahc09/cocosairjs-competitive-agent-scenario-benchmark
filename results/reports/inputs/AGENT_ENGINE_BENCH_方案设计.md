# Agent 双引擎对照实验方案 v2：Three.js r186 vs Cocos AIR

> 设计日期：2026-09-29（v2，同日重设计）
> 实验问题：**同一份复杂场景简报、同一 Agent 配置下，两个引擎各自能把 AI Agent 的"效果级 3D 场景开发"支撑到什么程度？差距在哪些能力域，差多少，为什么？**
> v2 变更：应"不要单 API 简单任务、要复杂效果场景"的要求，任务集从 12 个单功能任务重构为 10 个复杂场景简报（每个 200–500 行代码量级的迷你应用）；判分引入盲选 Elo 排名与动效录屏；预算与参照实现成本相应上调。

## 0. 设计依据（检索到的现有实践）

| 来源 | 借鉴点 |
|---|---|

提示词形态选择：Astra 社区流行**一句话提示**（模型自由发挥设计），但那会让结果差异混入"设计品味"方差；worldbuild-bench 明确用**结构化简报**隔离执行力。本实验目的是比引擎，故采用结构化简报（7 节式），只借用 Astra 的场景原型。

## 1. 实验问题与不回答的问题

**回答**：Agent 在"冷启动"与"带文档"两种知识条件下，用两引擎完成复杂效果场景开发的首过成功率、行为正确性、观感质量（盲评）、代码质量、效率成本；失败模式分布（API 幻觉、生命周期误用、渲染管线配置、性能不达标……）。

**不回答**：引擎运行时极限性能（帧率仅作场景功能性要求）；人工开发体验；编辑器生态。

**核心自变量**：引擎（three / cocosair）× 知识条件（C0 / C1）。**因变量**：客观分 + 盲评观感分 + Elo 排名 + 失败分类。

## 2. 公平性原则（P1–P8，实验有效性高于一切）

| # | 原则 | 落地手段 |
|---|---|---|
| P1 | **简报中性** | 简报只用领域语言与图形学术语（粒子、辉光、景深可说；Scene/Mesh/Component/OrbitControls 等 API 词禁说）；试点后冻结带版本号；引擎词黑名单脚本检查 |
| P2 | **Agent 配置恒定** | 同一模型版本、温度 0.2、同工具集、同预算（**最大 50 轮**、统一 token 上限、统一超时） |
| P3 | **知识条件对称** | C0=训练知识 + 包内 README + `.d.ts`；C1=另给 token 对齐 ±20% 的精选文档（两引擎同任务域同篇幅）；均禁联网检索 |
| P4 | **依赖边界对称** | 仅第一方扩展：three 模板预装 `three/addons` 与 **cannon-es**（与 AIR 内置 @cocos/cannon 同源物理，语义最接近）；AIR 模板预装其随包资源；lockfile 冻结，禁装新依赖 |
| P5 | **验证通道引擎无关** | 全部走"视觉 + 坐标 + 录屏"通道：截图、视觉定位→指针事件、双帧/多帧差分、rAF 计帧、console 捕获、Playwright video；不读引擎私有对象结构 |
| P6 | **最小遥测契约** | 沿用 worldbuild-bench 验证过的做法，简报统一要求：`window.__appReady`（首帧后置 true）与 `window.__bench = { getState, reset }`（可返回任意可序列化状态）；两引擎各 5–10 行，无偏向。探针深度不依赖它（视觉通道兜底） |
| P7 | **盲评** | 截图/录屏以 engine-A/B 匿名重命名后才进入评审；评审者与判定模型不接触代码、引擎名、目录名 |
| P8 | **可复现** | 资产本地化、模型版本与提示词版本写入报告、每轮全量工件归档（代码/agent 日志/录屏/截图/评分 JSON） |

**知识不对称的坦白**：Three.js 训练语料占压倒性优势，C0 测的是现实冷启动能力（对 AIR 真实但不公平的起点）；C1 测文档面能否扳回。**C1−C0 差值是头条结论之一**，直接验证路线图"知识包即护城河"假设。

## 3. 实验矩阵

```
运行 = 场景简报(10) × 引擎(2) × 知识条件(2) × 重复(N)
```

| 层级 | 范围 | 运行数 | 用途 |
|---|---|---|---|
| Pilot | E01/E03/E06/E10 × 2 × C0 × 1 | 8 | 校准简报与 harness；之后冻结简报 v1.0 |
| Tier-1 核心 | E01–E10 × 2 × 2 × N=3 | 120 | 主结论 |
| 加密（可选） | 头条场景 N=5 | +48 | 头条数字稳定性 |

复杂场景单 run 成本高（代码 200–500 行、50 轮预算），N=3 只报粗差异（0/3 vs 3/3 为确定性差距；1–2/3 报趋势并看失败模式）。矩阵内运行交错随机化，防模型版本漂移。盲评 Elo 需要的对比量：每场景 ≥20 对 → 10 场景 ≥200 次两两投票（评审为判定模型 + 抽样人工复核 10%）。

## 4. 场景简报集（10 个复杂效果场景）

选材原则：① 原型已被社区验证"AI 能做出效果"（Astra 目录/worldbuild-bench 同量级）；② 每场景复合 3–6 个子系统（程序化生成、大规模粒子、着色/后效、动画、交互、UI、音频、性能），杜绝单 API 面；③ 简报可用中性语言完整钉死验收；④ 两引擎原则上都可解（参照实现阶段证伪者标"引擎不可行"单列）。

简报统一模板（7 节式，两引擎一字不差，约 30–45 行）：

> **1 目标**：一句话定位。**2 视觉方向**：配色/氛围/风格锚点。**3 世界构成**：场景元素清单与布局参数。**4 交互与反馈**：输入→响应明细。**5 性能与尺度**：数量级与帧率要求。**6 技术约束**：工作目录已装 TypeScript 引擎与构建配置；单页面；不引入新依赖；画布 `#GameCanvas`；不依赖外部网络。**7 完成标准**：`npm run build` 通过、Chromium 打开无控制台错误、首帧后 `window.__appReady=true`、提供 `window.__bench={getState,reset}`。

## 6. Agent 执行协议

| 项 | 规定 |
|---|---|
| 模型 | 单一模型版本 pin，温度 0.2，写入每轮 run 元数据 |
| 系统提示 | 通用 web 创意工程角色；无引擎偏好；资源仅限工作目录与（C1 时）docs 目录 |
| 预算 | **最大 50 轮**工具调用（复杂场景代码量所需）、统一 token 上限、超时按"未完成"计 |
| 禁止 | 联网检索；安装新依赖；修改 harness/与 briefs/；触碰另一引擎目录 |
| 终止 | Agent 自评完成或预算耗尽；**不提供中间反馈**（单轮独立；迭代修复协议留作扩展 R2） |
| 重复 | 同 cell 的 N 次全新会话、全新目录副本，互不可见 |

## 7. 验证 harness 与判分模型

### 7.1 验证流程（每 run，引擎无关）

1. `npm run build` 通过性（失败即止，后续 0 分）
2. 静态服务起页面 → 等 `window.__appReady`（上限 90s）→ 捕获 console
3. **多步场景探针**（吸取 worldbuild-bench"门禁放行一切"的教训）：按简报逐条执行交互序列——视觉定位目标→指针/滚轮/键盘事件→等待→再采样；每步产出通过/失败与中间截图；`__bench.getState/reset` 做状态级断言（视觉通道兜底）
4. 采集：关键阶段截图 ≥5 张、**20–30s 自动交互录屏**（Playwright video，动效判定的唯一可靠通道）、rAF 帧率、静止期双帧
5. 盲评材料准备：截图+录屏匿名化（engine-A/B 映射表另行保管）

### 7.2 判分模型

**客观分（自动，60 分）**：

| 维度 | 分值 | 判定 |
|---|---|---|
| S1 可运行 | 15 | 构建 + `__appReady` + 无未捕获错误 |
| S2 行为探针 | 30 | 多步场景探针逐条通过率 |
| S4 代码质量 | 10 | tsc 通过、无 any 滥用、静态资源清理检查 |
| S5 效率 | 5 | 轮次/token/时长逆序归一 |

**观感分（盲评，40 分）**：六维锚点评定，每维 0/1/2/3 档（锚点文案随简报附）：构图取景 / 材质光影 / 动效流畅 / 特效质感 / 交互手感 / 整体完成度。raw 0–18 映射为 40 分制。

**Elo 排名（独立头条，不进 run 级分数）**：同场景内两引擎 run 两两盲选（录屏优先），≥20 对/场景，Bradley-Terry 拟合；报告引擎间 Elo 差与置信区间。判定模型投票 + 10% 人工复核抽样。

诊断指标（单列不入分）：HFL 人修行数（与参照实现 diff）；无效 API 引用率（import/调用名比对 `.d.ts`）；分段耗时（生成/调试/自测）。

### 7.3 参照实现（关键前置，成本上调）

每场景 × 每引擎由**人**完成参照实现（预计每个 0.5–1 人日，合计 10–20 人日）：① 证明可解性与简报清晰度（参照实现需要猜的地方改简报）；② 产出参照截图/录屏供盲评锚定与探针校准；③ AIR 侧参照实现直接沉淀为路线图 W1.8 迁移样例与 Gallery 候选——**这是实验之外最大的复利**。证伪者标"引擎不可行"并在报告单列。

### 7.4 失败分类

`API-幻觉 / 生命周期误用 / 渲染管线配置 / 着色与后效不达标 / 性能不达标 / 交互实现错误 / 类型错误未解 / 预算耗尽 / 引擎不可行`。

## 8. 报告模板

1. 头部：模型/引擎/简报版本/N/日期
2. **头条双指标**：各场景两引擎客观分中位数 + Elo 排名差
3. 六维观感画像（按难度分段）
4. 知识条件差值：C1−C0 每引擎提升（文档面回报率）
5. 失败分类矩阵 + 案例研究（每引擎最佳/最差各 2：简报→代码→录屏→失败点）
6. 诊断指标：HFL、无效 API 引用率、token 成本
7. 结论回灌路线图：§3 缺口表逐条印证/修正；AIR 后处理/着色自由度缺口的实测影响量化

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 复杂场景结果方差大（同 cell 内 run 间差异大） | N=3 起步、报中位数与分布；头条场景加 N=5；方差本身入报告（引擎稳定性差异是结论不是噪声） |
| 简报隐性偏向某引擎 | 试点冻结 + 黑名单脚本 + 第三方会话审词；参照实现双引擎各写一遍，措辞疑点即改 |
| AIR 后处理/折射不可行波及 E05/E09 | 简报只约束观感不约束手段；参照实现先行证实/证伪；不可行项单列不计入引擎能力总分 |
| 自动探针"放行一切"（worldbuild-bench 实测教训） | 探针为多步深度场景脚本 + 状态断言 + 录屏盲评三层兜底 |
| 录屏/截图判动效有损 | 录屏 30fps 起、固定交互脚本驱动；判定 prompt 与引擎无关；10% 人工复核 |
| 判定模型自身偏好 | 盲评 + 档位锚点 + 同批内交错；Elo 只在同场景内比较 |
| 模型版本中途更新 | 矩阵交错 + 单版本内跑完 + 版本入报告 |
| Agent 破坏协议（联网/装包/改 harness） | 模板无外网白名单、lockfile 冻结、工件审计日志 |
| B 阶段成本超支 | 四场景先行的裁剪路径；AIR 参照实现复用为官方示例，成本部分转化为产品资产 |
