# E07 — Cocos AIR 实例化/批处理规模天花板实测(ceiling-notes)

- 日期:2026-10-02;机器:本 bench 运行环境(Windows,Chrome headless 硬件 WebGL2,1280×720,vsync 60)
- 方法:工作区源码按参数改规模生成临时副本(mkstress.mjs,确定性同路径),逐档跑同一条 validate 流程(fps = harness 3s rAF 采样;spec 探针同步验证行为不回归)。
- 所有档位提交结构与交付版完全一致:**楼+窗 = 2 个合并静态网格(2 draw call);车/街灯/信标 = 1 个动态网格;雨/霓虹 = 1 个动态网格;地面/天空各 1;总 draw call 恒 ≈7,与规模无关。**

## 2. 瓶颈定位(定性)

- **CPU 动态网格写放是第一瓶颈**:雨每帧全量重写 6 顶点/粒子(9 floats/顶点)。10k 粒子 ≈ 54 万 float 写/帧(无感);100k 粒子 ≈ 540 万 float 写/帧 + 60 万顶点 bufferSubData(S7 掉帧主因之一)。
- **静态合并网格几乎免费**:楼 240→864(含窗阵顶点 13 万→50 万)帧率无变化;生成耗时 50→300ms(一次性/reset 时)。
- **fill rate 未触达**:720p + additive 少量大光斑;分辨率或光斑面积大幅上调才会触顶。
- **vsync 60 封顶**:60fps 以上的真实余量本方法测不出(帧率不会超过 60)。

## 3. 路径对比(与 E03 结论合并)

| 路径 | draw call | 规模伸缩 | 逐实例动画 | 结论 |
|---|---|---|---|---|
| 共享网格 × N 节点(E03 实测) | 线性增长(600 节点仍 60fps) | 受 draw call 预算限制 | 天然(节点变换) | 小规模可用,数百以上不经济 |
| **合并静态网格(本场景楼/窗)** | 恒 1 | CPU 生成 + GPU 顶点吞吐,1.5k 楼无压力 | 无(需重建) | 静态大批量最优 |
| **动态网格 updateSubMesh(本场景雨/车/霓虹)** | 恒 1 | CPU 写放预算 ~10 万 quad/帧 @60fps | CPU 顶点重写 | 动态大批量唯一路径;10 万 quad/帧为实测预算锚点 |

## 4. 对 Agent 的可执行建议(AIR 路线图输入)

1. 楼/窗等静态大批量:生成期合并 + 顶点色,勿逐节点 MeshRenderer。
2. 雨/车流/粒子:单动态网格 + updateSubMesh;粒子预算 60fps 下 ≤5 万(留 CPU 余量),≥30fps 场景可到 ~10 万。
3. 雾:用引擎 FogInfo(app.run 前配置避免二次编译;运行时切换接受单帧 ~100ms 重编译)。
4. 亮度标定:显示值 = 存储值²(无输出 gamma),夜景先按 sqrt 反解再上屏。
5. 自带包围盒:自建几何一律显式 minPos/maxPos,否则静默剔除。
